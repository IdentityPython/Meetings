# DRAFT — IdentityPython communications strategy

_Governance & Fork Review workstream · coordinated by Laura Paglione · draft started 12 Nov 2026_

> [!NOTE]
> **This is a starting draft, written in the shape we expect the final version to take.**
> Sections marked ✍️ **Needed** are where the workstream needs your input. The starting positions come from workstream meeting notes and Alessandro's [gap analysis](IdentityPython_Gap_Analysis_Against_Open_Source_Best_Practices.md). They are proposals, not decisions. A summary of what's needed is [at the end](#whats-needed-to-finish-this-draft).

**The goal:** anyone, whether a user, contributor, or maintainer, can find out what's happening in IdentityPython, where to ask, and where decisions are recorded.

**One principle:** if it was decided, it's written down on GitHub. Chat is for quick conversation; GitHub is the record.

---

## Where to go for what

| I want to… | Go to |
|---|---|
| Learn what a project does, its status, and who maintains it | [idpy.org](https://idpy.org) and the project's README |
| Report a bug or request a feature | The project's GitHub issues |
| Report a security vulnerability | The [private security reporting process](https://github.com/IdentityPython/Governance/blob/master/idpy-incidentresponse.md). Never a public issue |
| Ask a question or get help | ✍️ _[mailing list / Slack / GitHub Discussions?]_ |
| Chat with maintainers and contributors in real time | IdentityPython Slack ✍️ _[how to join]_ |
| Follow the re-engagement work | The [Meetings repository](https://github.com/IdentityPython/Meetings) (notes, agendas, and [artifacts](README.md)) and the [meeting calendar](https://www.addevent.com/calendar/tt4fnvvjjnsk) |
| Hear about releases | ✍️ _[GitHub Releases / mailing list / both?]_ |

> ✍️ **Needed:** list the current mailing lists, what each is for, and whether it's still active. Spam has been a problem on at least one list. Project docs should also point to the right list; for example, SATOSA's contribution guide doesn't mention the SATOSA mailing list.

## The website

idpy.org is the front door. For each project, it should show:
* what the project does
* its **status** (see [project status](2026-11%20DRAFT%20IdPy%20Roles%20and%20Maintainer%20Model.md#project-status))
* its **maintainers**
* links to its code and docs, eventually through a single docs portal

It should also show how the projects relate to each other. Alessandro's [project map](IdentityPython_Project_Map_By_Protocol_and_Type.md) is a starting point.

> ✍️ **Needed:** someone to review the website against the current list of repositories and remove or relabel outdated projects. The security page, for example, appears to list older libraries.

## Regular updates

| What | When | Who |
|---|---|---|
| Meeting notes in the Meetings repo | After each workstream meeting | Coordinator |
| "Current asks" on the [artifacts page](README.md) | Weekly | Coordinator |
| Community town hall | About twice a year (June 2026; next planned for December 2026) | Coordinator, with the workstreams |
| Release announcements | Each release | Project maintainers |

> ✍️ **Needed:** confirm this rhythm is sustainable, and who can post announcements on behalf of IdentityPython.
