IdPy Workstream: GOVERNANCE & FORK REVIEW
==================================

This folder contains meeting notes for the combined **Technical Governance** and **Fork Review** workstream.

> _**About this workstream:** In November 2026, the [Governance](../Workstream-Governance) and [Fork Review](../Workstream-Fork%20Review) workstreams were combined because of significant overlap in participation and content. Notes from meetings held before the merge remain in those folders (see [Past Meetings](#past-meetings) below)._
>
> _Documents produced by the workstreams (drafts, proposals, inventories, etc.) are collected in the shared [Artifacts](../Artifacts) folder._

## KEY DELIVERABLES IN SCOPE

**Technical governance**
* Defined and functioning maintainer model
  * Documentation release process
  * Documented contributor guidelines
* Documented technical governance workflow
  * Vulnerability report process
  * Clear contributor ladder
* Regular technical coordination meetings in operation

**Fork review**
* Catalog of forked projects and what they contain
* Prioritized integration roadmap
* Guidelines to outline the integration approach

## GOALS
* Releasing can be done easily and often
* Any authorized maintainer or group can cut a release
* Automate releases
* Facilitate SCA/SBOM
* OIDC Trusted publishing workflow
* Coding standards implemented as automated quality gates
* Get access to known but private forks

## TASKS
* Consider common practices
  * Release automation?
  * PyPI org creation? | PyPI project ownership transfers?
  * Automate contributor privilege management?
* List out all the forks
* Fork review and develop merge plans
* Prioritize security concerns and potential already existing fixes
